## A. 제품 정체성과 게임 디자인 원칙

### A-1. 한 줄 정의
**"오늘 하루를 살았다는 사실만으로, 나만의 판타지 역사가 한 페이지씩 쓰이는 앱."**

### A-2. 핵심 정체성
| 축 | 데일리-데일리는 | 데일리-데일리는 아니다 |
|---|---|---|
| 목적 | 삶을 **기록하고 의미를 부여** | 생산성 강요·습관 교정 도구 |
| 보상 대상 | 모든 행동(잠·식사·멍때리기 포함) | 공부·운동만 |
| 게임성 | 발견·수집·서사 | 경쟁·랭킹·손실 공포 |
| 정보 밀도 | 로비는 최소, 상세는 단계적으로 | 대시보드형 수치 나열 |

### A-3. 디자인 원칙 (모든 기능 판단 기준)
1. **모든 날은 가치 있다.** 아무것도 안 한 날, 아픈 날에도 그날을 설명하는 고유한 용사 유형과 서사가 존재한다.
2. **몸을 희생시키지 않는다.** 수면 부족·결식·과운동은 보상 조건이 되지 않는다. 오히려 회복·충분한 수면이 전설 조건에 들어간다.
3. **기록 남발을 보상하지 않는다.** 보상은 "기록 개수"가 아니라 "하루의 형태(조합·흐름·지속)"에 반응한다. 이벤트는 하루 상한과 감쇠가 있다.
4. **3초 기록, 30초 정밀 기록.** 빠른 저장이 기본, 세부 항목은 접혀 있다.
5. **결정적(deterministic) 판정.** 같은 기록 → 같은 결과. 랜덤은 시드 기반으로 재현 가능해야 한다.
6. **수정은 자유, 보상 악용은 불가.** 기록 수정은 결산을 재계산하지만 이벤트 보상은 원장(ledger)으로 1회만 지급된다.
7. **로비는 무대, 숫자는 백스테이지.** 홈에는 캐릭터·오늘의 진행·세계 배경·기록 진입점만.
8. **AI는 양념.** 핵심 게임 로직과 서사는 사전 제작 콘텐츠 + 템플릿으로 돌아가며, 유료 AI API 없이도 100% 동작한다.

### A-4. 세계관 (콘텐츠 일관성의 기준)
- 세계 이름: **아스테리아(Asteria)** — 사람들의 "하루"가 별빛(에테르)이 되어 세계를 유지하는 대륙.
- 사용자: 기억을 잃은 **"하루의 기록자(Chronicler)"**. 하루를 기록할 때마다 잊힌 대륙의 지역이 복원된다.
- 안내 NPC: **서기관 올빼미 "모르가"**(연대기/결산 담당), **여관주인 "브람"**(식사·휴식), **대장장이 "이그니스"**(개발·장비), **도서관 사서 "세렌"**(공부·독서), **기사단장 "레온하르트"**(운동), **숲의 정령 "피오"**(명상·휴식·수면).
- 톤: 따뜻한 하이 판타지. 비꼬거나 훈계하지 않는다. 사용자를 탓하는 문구 금지("오늘도 게을렀군요" ✗).

## B. 화면별 UX 및 사용자 흐름

### B-0. 전역 구조
- 모바일 퍼스트(기준 390×844), 데스크톱은 중앙 480px 폭 "게임 프레임" + 양옆 배경.
- 하단 탭 5개: **홈 / 연대기 / (+) / 도감 / 모험가**. 중앙 +는 탭 높이보다 18px 솟은 원형 문장(紋章) 버튼.
- 최소 글자 크기 14px(본문 16px), 터치 타깃 44px 이상, 한 화면 카드 최대 3~4개.
- 폰트 제안: 제목 — 판타지 세리프(예: `Cinzel`(영문)/`Nanum Myeongjo` 계열), 본문 — `Pretendard`. 라이선스 확인된 웹폰트만.

### B-1. 첫 화면(타이틀)
1. 배경: 현재 시간대의 아스테리아 전경 + 로고 "Daily Daily".
2. **[모험 시작]** 버튼 → 이 사용자 제스처에서 AudioContext 해제·BGM 페이드인(1.5s). (브라우저 자동재생 정책 준수)
3. 비로그인 → 로그인/회원가입 → 첫 방문 온보딩(3단계: 이름 짓기 → 시간대 확인(자동 감지, 수정 가능) → 캐릭터 외형 선택 4종).
4. 이미 로그인 & 당일 세션 재방문 시 타이틀 생략 옵션(설정: "타이틀 화면 건너뛰기"). BGM은 "재생하려면 탭" 작은 토글로 처리.

### B-2. 홈(로비)
화면 구성(위→아래), **이 외의 요소를 추가하지 않는다**:
- 상단 얇은 바: 캐릭터 이름 · Lv · 날짜(9월 23일 수) · 🔊 토글.
- 중앙 무대(화면의 55%): 시간대별 배경 + 캐릭터 일러스트(아이들 애니메이션: 호흡, 망토 흔들림). 캐릭터 머리 위 말풍선에 NPC/캐릭터의 한 줄 대사(상황 기반).
- **오늘의 모험 진행도**: 원형이 아닌 "여정 두루마리" 1줄 — 오늘 기록한 카테고리 아이콘이 발자국처럼 이어짐 + "오늘의 기운: 탐구 ●●●○○" 같은 간단 표시 1개.
- 이벤트 알림 배지(미확인 이벤트/어제 결산 결과가 있을 때만): "어젯밤, 모르가가 당신의 하루를 기록했습니다 → 확인".
- 진행 중 기록(예: 수면 중, 공부 타이머 진행 중)이 있으면 무대 하단에 "📖 공부 중 · 00:42 [종료]" 칩 1개.

**시간대 배경 (사용자 로컬 시각 기준)**
| 시간 | 장면 | 연출 |
|---|---|---|
| 05–07 | 여명 | 지평선 해돋이, 안개 |
| 07–11 | 아침 | 맑은 하늘, 새 |
| 11–16 | 낮 | 밝은 성채, 구름 흐름 |
| 16–19 | 황혼 | 주황 하늘, 등불 켜짐 |
| 19–22 | 밤 | 달, 창문 불빛 |
| 22–05 | 심야 | 별 반짝임(CSS/Canvas 파티클), 오로라 가끔 |
구현: 레이어드 SVG/WebP(하늘·원경·중경·전경) + CSS 그라데이션 보간 + 경량 파티클. `prefers-reduced-motion` 시 애니메이션 최소화. 날씨는 v2(실제 날씨 API 사용 안 함, 랜덤 연출만 선택적).

### B-3. + 버튼 → 행동 공 메뉴(Orb Menu)
- 탭 시: 배경 딤(블러) + 중심에서 공들이 **스프링 애니메이션**으로 방사형 전개(첫 페이지 최대 8개, 반경 ~130px, 순차 지연 30ms). 햅틱(`navigator.vibrate(10)` 지원 시).
- 공 = 카테고리. 각 공은 고유 색·아이콘·문장. 예) 수면(남색 달), 식사(주황 빵), 공부(청록 마도서), 운동(적색 검), 개발(보라 톱니·룬), 휴식(초록 잎), 명상(하늘 연꽃), 독서(갈색 책), 창작(분홍 깃펜), 여가(노랑 주사위), 외출(연두 지도), 인연(금색 하트 — 가족·친구), 생활(회색 빗자루 — 집안일·위생), 커스텀.
- **첫 페이지 정렬**: 최근 14일 사용 빈도 × 시간대 적합도(지금 시각에 자주 쓰던 카테고리 가중) 상위 7개 + "더보기(…)" 공. 사용자가 길게 눌러 고정(핀) 가능 — 핀이 자동 정렬보다 우선.
- 좌우 스와이프 또는 "더보기" → 2페이지(나머지 + "새 행동 만들기" 공).
- 진행 중 기록이 있으면 해당 공에 빛나는 테두리 + 탭 시 "종료" 바로가기.
- 공 탭 → 공이 확대되며 **세부 행동 시트**(bottom sheet)로 전환(공유 요소 전환 애니메이션).

### B-4. 세부 행동 시트 & 공통 입력 폼
1. 상단: 세부 행동 칩(즐겨찾기 먼저) — 예) 공부: `수학`, `영어`, `+ 새 과목`.
2. 칩 탭 → 폼. **기본 노출 필드는 2~3개**:
   - 시간 모드 3종 스위치: **[지금 시작(타이머)] [방금 끝남(지속시간)] [시간 지정]**
   - 핵심 필드 1~2개(카테고리별, 아래 참조)
   - 기분(5단계 이모지, 선택)
3. **"자세히 기록 ▾"** 펼치면 고급 필드.
4. 저장 버튼은 항상 하단 고정. 최소 입력 저장 = 칩 탭 → 저장(2탭).
5. 시각 수정: 모바일 **시·분 휠 피커**(5분 단위 기본, 길게 눌러 1분 단위), "어제" 토글로 전날 기록 가능. 종료 < 시작이면 자정 넘김으로 자동 해석하고 "다음날 07:10" 표기.
6. 저장 후: 공이 캐릭터에게 날아가 흡수되는 연출(0.6s) → XP 토스트 → (확률 충족 시) 이벤트 카드 연출.

**카테고리별 필드(기본 / 고급)**
| 카테고리 | 기본 필드 | 고급 필드 |
|---|---|---|
| 수면 | [잠자기]/[기상] 버튼 | 취침·기상 시각, 수면 유형(밤잠/낮잠/쪽잠/선잠·밤샘 후), 입면 소요, 중간 각성 횟수, 기상 상태(개운/보통/피곤/매우 피곤), 만족도 1-5, 꿈 메모 |
| 식사 | 식사 종류(아침/점심/저녁/간식/야식), 식사량(거의 못 먹음/조금/적당히/든든히/과식) | 메뉴(자유 입력+자동완성), 형태(집밥/외식/배달/간편식), 함께한 사람, 만족도, 사진 없음(v1) |
| 공부 | 과목(직접 입력, 자동 저장·즐겨찾기), 시간 | 방식(강의/독학/문제풀이/암기/복습/스터디), 문제 수·정답 수, 페이지, 이해도 1-5, 집중도 1-5, 메모 |
| 개발 | 프로젝트명(자동 저장), 시간 | 작업 종류(기능/버그/리팩터/설계/리뷰/배포/학습), 결과(완료/진행/막힘), 해결한 문제 수, 커밋 수, 메모 |
| 운동 | 종목, 시간 | 종목별 전용 필드(아래), 강도(RPE 1-10), 심박(선택) |
| 명상 | 시간 | 방식(호흡/바디스캔/걷기명상/기도), 전후 기분 |
| 휴식 | 종류(멍/산책/차 한잔/낮잠 아님 휴식/음악) | 시간, 회복감 1-5 |
| 독서 | 책 제목(자동 저장), 시간 | 페이지, 장르, 완독 여부, 한 줄 문장 |
| 창작 | 분야(글/그림/음악/영상/공예), 시간 | 작품명, 진척, 완성 여부 |
| 여가 | 종류(게임/영상/음악감상/취미) | 시간, 만족도 |
| 외출 | 목적(산책/쇼핑/여행/카페/자연) | 장소 메모(좌표 수집 안 함), 시간 |
| 인연 | 대상(가족/친구/연인/동료/반려동물), 활동 | 시간, 유대감 1-5 |
| 생활 | 집안일/위생/정리/장보기 | 시간 |

**운동 종목별 전용 입력 (`metricSchema`)**
- 근력(스쿼트·벤치·데드·풀업 등): 세트 반복 리스트 `[{weightKg, reps}]` + "세트 복사" 버튼
- 유산소(걷기·달리기·자전거·수영·등산): 거리(km), 시간, 페이스 자동 계산, 걸음 수(걷기)
- 유연성(스트레칭·요가·필라테스): 시간, 부위
- 구기·스포츠(축구·농구·배드민턴·테니스·클라이밍 등): 시간, 경기 수/결과(선택)
- 기타: 시간, 강도

### B-5. 수면 흐름 (자정 경계 핵심)
- **[잠자기]** 탭 → 진행 중 수면 레코드 생성(start=now). 홈이 "잠든 세계"(어두운 필터 + 반딧불) 모드, 탭 시 "좋은 꿈을" + BGM 자동 음소거 옵션.
- **[기상]** 탭 → end=now, 기상 상태·만족도 1탭 입력 시트.
- 수면 유형 자동 추천: 시작 시각이 10:00–18:00이고 길이 < 3h → 낮잠, 그 외 밤잠. 사용자 변경 가능.
- **수면의 날짜 귀속**: 밤잠은 **기상 시각이 속한 날짜**에 귀속(= "그날을 위한 잠"). 낮잠은 시작일에 귀속. 레코드에 `attributedDate`를 저장하고 수정 가능.
- 기상 누락 방지: 수면 진행 16시간 초과 시 다음 앱 진입에서 "기상 시각을 알려주세요" 휠 피커.

### B-6. 이벤트 연출
- 저장 직후 발생 시: 화면 어두워짐 → 희귀도 색 빛기둥(일반 은색 / 희귀 청색 / 영웅 보라 / 전설 금색 + 전용 효과음) → 카드 뒤집기.
- 카드: 희귀도 라벨, 제목, 발생 조건(한 줄), 본문 2~4문장, NPC 대사 1줄, 보상 라인. 버튼 [받기] / [연대기에 기록됨].
- 하루 이벤트 연출은 최대 3회, 초과분은 조용히 "우편함"에 적재(방해 최소화). 설정에서 "이벤트 연출 간소화" 가능.

### B-7. 일일 결산 화면 (다음 접속 시 1회)
- 모르가가 두루마리를 펼침 → "9월 22일, 당신은…" → 용사 유형 카드 공개(신규면 "NEW! 도감 등록" 도장).
- 표시: 유형명, 희귀도, 한 줄 정의, 판정 근거 3개(예: "개발 5시간 12분", "해결한 문제 4개", "충분한 수면 7h 40m"), 오늘의 모험 일지(4~6문장), 획득 보상.
- 결산 재계산 시: "기록이 수정되어 9월 22일의 역사가 다시 쓰였습니다" 알림(이전 결과는 히스토리에 보존).

### B-8. 연대기(Chronicle)
- 기본: 월 달력. 각 날짜 칸에 **그날 용사 유형의 작은 문장(엠블럼)**, 전설/영웅은 테두리 빛. 미결산(오늘)은 모래시계.
- 날짜 탭 → **모험 일지 페이지**(양피지 스타일, 세로 스크롤):
  1. 헤더: 날짜, 용사 유형 카드
  2. 모험 서사(템플릿 생성)
  3. 하루 타임라인(시간순, 카테고리 아이콘, 탭 시 세부/수정)
  4. 섹션 요약: 수면 · 식사 · 공부 · 운동 · 개발 · 기타 (값이 있는 섹션만)
  5. 그날의 이벤트, 획득 아이템, 달성 업적
  6. [기록 추가/수정] 버튼(과거 날짜 편집 → 재결산 예약)
- 상단 탭: **달력 / 연표(주요 사건만 모은 타임라인: 첫 전설, 신규 지역 개방, 연속 퀘스트 완료 등) / 보관함(아이템·이벤트·업적)**.

### B-9. 도감(Codex)
- 탭: **용사 유형(100) / 이벤트 / 아이템 / 지역·NPC**.
- 용사 유형 그리드 5열: 미발견 = 검은 실루엣 + "???" + 희귀도 테두리만, 힌트는 일부만(발견률에 따라 힌트 1줄 공개: 예 "새벽과 마도서를 사랑하는 자…").
- 발견 카드 상세: 일러스트, 이름, 설명, 획득 조건(발견 후 전문 공개), 획득 횟수, **획득한 날짜 목록(탭 → 연대기 해당 날짜)**.
- 상단 진행도: "발견 23 / 100".

### B-10. 모험가(Profile)
- 캐릭터 전신 + 장비 슬롯(무기/방어구/장신구/망토 — 순수 외형, 수치 우위 없음).
- 6대 특성 헥사곤 차트 + 레벨/XP, 칭호 선택.
- 세계지도 진입, 업적, 연속 퀘스트 진행, 설정.
- **설정**: BGM on/off·음량 슬라이더, 효과음 on/off·음량, 타이틀 건너뛰기, 이벤트 연출 간소화, 시간대, 하루 시작 기준 시각(기본 00:00, 야행성 사용자 위해 최대 04:00까지 "하루 경계" 조정 — v1은 00:00 고정 + 필드만 준비), 커스텀 행동 관리, 데이터 내보내기(JSON/CSV)·가져오기, 계정 삭제.

### C-1. 시간 규칙
- 모든 시각은 UTC `timestamptz` 저장, 표시·귀속은 `UserProfile.timezone`.
- `attributed_date` = 로그 시작 시각의 현지 날짜(수면 밤잠은 기상 현지 날짜). 사용자가 수동 변경 가능.
- 자정을 넘는 일반 활동(예: 23:00–01:30 개발): 시작일 귀속을 기본으로 하되, 결산 특징 계산 시 **분 단위로 날짜별 분할 집계**(23:00–24:00=60분은 전날, 00:00–01:30=90분은 다음날)를 적용한다. `attributed_date`는 연대기 표시용, 분할 집계는 판정용. → "밤샘형" 유형 판정에 필요.
- 시간대 변경(여행): 변경 이후 로그부터 새 시간대 적용. 과거 결산은 재계산하지 않음(원장 보존).

### C-2. 커스텀 행동 시스템
- 사용자는 **카테고리**(이름·아이콘 40종 중 택1·색)와 **세부 행동**을 생성.
- 생성 마법사 3단계:
  1. 이름/아이콘/색
  2. **"이 행동은 어떤 힘을 키우나요?"** — 6대 특성 중 최대 2개 선택(주 70% / 부 30%), 또는 "성격 태그" 선택(몸/마음/지식/창작/관계/회복/생활) → 태그가 특성 가중치와 용사 판정 그룹에 매핑
  3. 기록 방식 템플릿 선택: `duration`(시간), `count`(횟수), `sets`(세트·횟수·중량), `distance`, `check`(했음/안 했음), `rating`(만족도)
- RPG 연결 규칙:
  - XP: 커스텀도 시스템 행동과 **동일한 XP 곡선**(시간 기반) → 커스텀으로 XP 뻥튀기 불가.
  - 용사 판정: 커스텀 로그는 태그의 **판정 그룹**(body/mind/knowledge/craft/social/recovery/life)으로 합산되어 기존 100유형 판정에 참여.
  - 이벤트: 커스텀 전용 "범용 이벤트 풀"(태그 기반, 예: `tag:body` 이벤트) + 커스텀 이름을 템플릿에 삽입("당신의 {행동명} 수련이…").
  - 도감: 커스텀 카테고리를 30일 중 10일 이상 기록하면 "고유 비전서(秘傳書)" 아이템 1개 생성(사용자 행동명 각인) — 개인화된 수집품.
- 새 카테고리 생성 시 + 메뉴에 새 공이 생성되고 "새로운 힘의 구슬이 탄생했습니다" 연출.

## D. RPG 시스템 상세 규칙

### D-1. 6대 특성
**지식(INT) · 체력(STR) · 창의(CRE) · 회복(REC) · 유대(BND) · 평정(CAL)**
- 각 특성 독립 레벨(1~99). 캐릭터 레벨 = 특성 레벨 합에서 파생: `charLevel = floor(sum(traitLevels)/6)`… 가 아니라 **특성 편중 방지** 위해 `charLevel = floor( (Σ traitLevel) / 6 + 0.5 × minTraitLevel )` 사용 → 고른 성장이 약간 유리하지만 한 특성만 키워도 성장은 멈추지 않음.
- 특성 레벨업 필요 XP: `need(L) = round(60 × L^1.5)`.

### D-2. 기록 XP (결정적, 남발 방지)
- 시간 기반: `xp = round(10 × min(duration_min, 240)^0.7)` (한 기록 240분 캡, 체감 곡선).
- 시간 없는 기록(check/count): 고정 8XP.
- **카테고리별 일일 체감**: 같은 카테고리의 당일 누적 XP가 200 초과 시 0.5배, 400 초과 시 0.2배.
- **하루 총 기록 XP 상한** 1,200. 상한 도달 후에도 기록은 되며 판정·연대기에는 반영(보상만 제한). 문구: "오늘의 에테르가 가득 찼습니다. 기록은 계속 역사로 남습니다."
- 수면: 7–9h 구간 최대 XP, 과소·과다는 XP 감소(벌점은 없음). 식사: 결식 벌점 없음, "적당히/든든히"가 최대.
- 기록 XP는 **당일 재계산형**: 원장에 `log_xp:{date}` 하나로 두고 결산 시 확정(수정 시 차액 갱신). 음수 XP 없음 — 줄어든 경우 표시 XP만 조정, 레벨 다운 없음(레벨은 최대치 유지).

### D-3. 이벤트 확률 & 제어
- 트리거 평가는 **로그 저장(완료) 시점**에만.
- 기본 발생 확률: 해당 로그와 매칭되는 이벤트 풀이 있을 때 `p = 0.25`(일반 70% / 희귀 22% / 영웅 6.5% / 전설 1.5% 가중) — 조건형 이벤트(조합·연속)는 조건 충족 시 확정 또는 고정 확률.
- **시드 난수**: `seed = hash(user_id, attributed_date, category_id, dailyCategoryOrdinal)` — 같은 날 같은 카테고리의 n번째 기록은 삭제 후 재입력해도 같은 결과(리롤 불가). `dailyCategoryOrdinal`은 삭제돼도 감소하지 않는 카운터(원장 기반).
- 하루 이벤트 상한: 확률형 3회 + 조건형(조합·연속) 2회. 같은 이벤트 하루 1회, `cooldown_days` 적용.
- **최소 의미 조건**: 시간형 기록은 10분 이상일 때만 이벤트 추첨(1분짜리 기록 남발 방지).
- 불운 보정(pity): 7일간 희귀 이상 미발생 시 다음 추첨의 희귀 가중 2배(부드러운 보정).
- 수정/삭제: 이미 발생한 이벤트와 보상은 유지(원장 UNIQUE). 단 "트리거 로그가 삭제됨" 플래그를 표시하지 않음(사용자 비난 금지). 악용은 시드 고정 + 원장으로 원천 차단.

### D-4. 아이템
- 분류: **소재**(마도서 조각, 별빛 모래 등 — 조합 재료), **장비**(외형 전용), **유물**(수집품, 도감), **소모품**(v2: 연출 효과만).
- 조합: 조각 5개 → 완성 유물(예: 마도서 조각×5 = "완전한 마도서" 유물 + 칭호). 수치적 이득 없음 → 과금·편중 유인 제거.

### D-5. 업적
- 공개 업적(60) + **비밀 업적(40)**. 조건은 결정적 규칙(`Rule DSL`, E-2 참조)으로 정의.
- 비밀 업적 예:
  - **"평범함의 미학"**: 7일 연속 수면 7–9h + 세 끼 기록 — 평범한 하루도 보상.
  - **"아무것도 하지 않을 용기"**: 하루 휴식 ≥ 180분 & 다른 생산 활동 0 & 기분 ≥ 4
  - **"새벽 두 시의 철학자"**: 00:00–04:00 사이 독서 또는 명상 기록(수면 ≥ 6h인 날만 — 밤샘 장려 금지)
  - **"비 오는 날의 수프"**: 같은 날 '집밥' 식사 + '휴식' + 기분 상승
  - **"백 번째 페이지"**: 누적 기록 100개 / 1000개
  - **"다시 돌아온 모험가"**: 14일 이상 공백 후 복귀 — 공백을 벌하지 않고 환영
  - **"모든 공의 주인"**: 시스템 카테고리 13개 모두 1회 이상
  - **"잠꾸러기의 전설"**: 잠꾸러기 현자 10회 획득

### D-6. 연속(스트릭) 정책
- **"연속 기록일"은 표시하되 끊겨도 벌점 없음**. 대신 "누적 모험일"을 주 지표로 표시.
- 휴식권: 주 1회 자동 "여관에서 쉬는 날" — 기록 없는 날도 스트릭 유지.

  | 고요의 첨탑 | 명상 누적 5h + 모든 기본 지역 개방 | 수도사 "엔" |
  | 시간의 성소 | 누적 모험일 100일 | 시간의 수호자(엔딩 NPC) |
- 지역마다 전용 이벤트 풀·배경 스킨(홈 배경을 개방 지역 중 선택 가능) → 수집 동기.

### D-8. 연속 퀘스트(체인)
- 조건 충족 시 시작, 단계별 조건은 "N일 이내 어느 날이든" 방식(매일 강요 금지). 만료 시 벌점 없이 "언젠가 다시" 상태로 휴면 → 재트리거 가능.
- 예시 체인:
  1. **잠든 용의 알 (3단계, 14일 이내)**: ① 밤잠 7h+ → 알 발견 ② 서로 다른 3일에 휴식/명상 → 알이 따뜻해짐 ③ 기분 4+인 날 → 아기 용 "모치" 부화(홈 펫으로 등장, 기록 시 반응).
  2. **이그니스의 전설 검 (4단계, 21일)**: 개발 "해결한 문제" 누적 5 → 운동 1회 → 개발 결과 "완료" 3회 → 창작 또는 독서 1회 → 외형 무기 "코드 브레이커".
  3. **세렌의 잃어버린 색인 (5단계, 30일)**: 서로 다른 과목 3개 공부 → 독서 완독 1권 → 문제풀이 50문항 누적 → 복습 방식 기록 2회 → 이해도 5 기록 → 유물 "만물의 색인".
  4. **브람의 비밀 레시피 (3단계)**: 아침·점심·저녁 기록한 날 → 집밥 3회 → 누군가와 함께한 식사 → 칭호 "여관의 단골".
  5. **피오의 계절 (4단계, 28일)**: 외출(자연) → 명상 → 7일 중 5일 수면 7h+ → 휴식 회복감 5 → 배경 스킨 "영원한 봄".

## E. 100가지 용사 유형

### E-1. 판정 파이프라인 (결정적)
1. **특징 추출** `extractFeatures(logs, date, tz) → DayFeatures` (순수 함수):
   - `min[group]`: 판정 그룹별 분(자정 분할 적용), `min[category]`
   - `sleepMin`(귀속일 밤잠), `napMin`, `wakeTime`, `bedTime`(전날 밤)
   - `meals`: 종류 set, 과식/거의못먹음 횟수, 함께 먹음 여부
   - `studySubjects` 수, `problems`, `avgFocus`, `avgUnderstanding`
   - `devSolved`, `devResult` 분포
   - `exerciseKinds`, `distanceKm`, `strengthVolume`
   - `moodAvg`, `moodDelta`(첫 기록 기분 → 마지막 기록 기분), `moodCount`
   - `activeGroups`(30분 이상 그룹 수), `logCount`, `firstLogTime`, `lastLogTime`
   - `timeOfDayProfile`: 새벽(04–07)/오전/오후/저녁/심야(22–04) 분포
   - `lateNightActiveMin`(00:00–04:00 비수면 활동)
   - `prevDay`: 전날 특징 요약(회복형 판정용), `eventsToday`(희귀도별)
   - `totalActiveMin` = 수면 제외 활동 합
2. **규칙 평가**: 100개 유형 각각 `condition(features): boolean`과 `score(features): number`(조건의 초과 정도, 0~1).
3. **선택**: 희귀도 우선순위 **전설 → 영웅 → 희귀 → 고급 → 일반 → 기본(폴백)** 순으로 조건 충족 유형을 찾고, 같은 층에서는 `score` 내림차순 → `No` 오름차순(결정적 타이브레이크).
4. **안전 규칙(모든 유형 공통 게이트)**: 전설·영웅 유형은 `sleepMin ≥ 360` **또는 수면 미기록**일 때만 가능(수면을 기록하지 않은 사용자를 차별하지 않되, 6시간 미만 수면 기록 시 상위 희귀도 차단 → 수면 희생 유인 제거). 결식은 어떤 유형의 조건에도 들어가지 않는다.
5. 결과 + `reasons`(조건 중 가장 기여한 3개 특징) + `rule_version` 저장.
6. `features`, 유형 정의는 버전 관리. 규칙 변경 시 과거 결산은 **재계산하지 않음**(당시 규칙 보존), 사용자 수정이 있을 때만 해당 날짜를 최신 규칙으로 재결산.

### E-2. 규칙 표기
`공`=knowledge 분(공부+독서), `공부`=study만, `개`=개발, `운`=운동, `창`=창작, `휴`=휴식, `명`=명상, `여`=여가, `외`=외출, `인`=인연, `생`=생활, `수면`=밤잠 분, `활동`=totalActiveMin, `그룹수`=activeGroups. 시간은 분 또는 h.

### E-4. 수집 구조
- 도감 등록: 첫 획득 시. 획득 횟수·날짜 목록 유지(날짜별 DailySettlement).
- 희귀도별 발견 보상: 신규 일반 30XP(전 특성 분배), 고급 50, 희귀 100, 영웅 200, 전설 400 + 칭호. **보상은 첫 획득 1회만**(RewardLedger `settlement_first:{heroId}`).
- 수집 세트(10종): 예) "마법사의 계보"(041·008·001), "기사의 길"(042·019·011·002), "쉼의 기술"(021·026·065·078·096) → 세트 완성 시 외형 장비.
- 재결산으로 유형이 바뀐 경우: 이전 유형의 도감 등록·첫 획득 보상은 **유지**(사용자 손실 없음), 해당 날짜 표시만 새 유형. 이를 악용한 반복 수정은 날짜당 재결산 결과로 인한 신규 도감 등록을 **하루 1회**로 제한하여 억제.

## F. 이벤트 콘텐츠 & 운영 구조

### F-1. 이벤트 정의 스키마 (코드 내 JSON/TS, 버전 관리)
```ts
type EventDef = {
  id: string;                       // "evt_grimoire_last_page"
  rarity: "common"|"rare"|"epic"|"legendary";
  kind: "chance"|"combo"|"streak"|"chain_step"|"milestone";
  trigger: RuleExpr;                // DSL: {all:[{cat:"study"},{field:"details.subject", contains:"수학"},{durationMin:{gte:60}}]}
  weight: number;                   // chance 풀 내 가중치
  chance?: number;                  // combo/streak 고정 확률(기본 1.0)
  cooldownDays: number;
  region?: string;                  // 개방 지역 필요 시
  title: string;
  body: string[];                   // 변형 문단 2~3종, {subject},{project},{minutes},{name} 변수
  npcLine?: {npc:string; text:string};
  rewards: { xp?: Partial<Record<Trait,number>>; items?: {id:string; qty:number}[]; title?: string; startsChain?: string };
};
```
`RuleExpr`는 `all/any/not`, `cat`, `type`, `tag`, `durationMin`, `field` 비교, `dayHas`(당일 다른 기록 존재), `after`(시간순 선행 기록), `streakDays`(최근 N일 중 M일) 연산만 지원 — 동일 DSL을 업적·유형·퀘스트에 재사용.

### F-3. AI 서사 생성 vs 사전 제작 비교
| | 사전 제작 + 템플릿 | 매번 LLM 생성 |
|---|---|---|
| 비용 | 0 | 사용자·기록당 과금 |
| 품질 일관성 | 높음(세계관 통제) | 편차·환각·톤 붕괴 위험 |
| 속도/오프라인 | 즉시 | 지연, 네트워크 의존 |
| 결정성/테스트 | 가능 | 어려움 |
| 개인화 | 변수 치환 수준 | 매우 높음 |
| 개인정보 | 외부 전송 없음 | 생활기록 외부 전송 |

**채택: 3층 혼합 구조**
1. **L1 코어(필수, 무료)**: 이벤트·유형·업적은 사전 제작. 일일 모험 일지는 **문장 조각 조합기**(도입부 20 × 사건 문장(카테고리·상황별 각 5~10) × 전환 문구 × 결말 20)로 생성. 시드 = hash(user, date) → 결정적.
2. **L2 선택(옵트인)**: 설정에서 "AI 서사 다듬기" 켜면, 이미 확정된 결산 결과(유형·주요 사건 요약만, 메모 원문 제외)를 LLM에 보내 일지 문장만 윤색. 환경변수 없으면 기능 자체 비노출. 월 호출 상한·캐시(날짜당 1회, 재결산 시에만 재생성).
3. **L3 운영**: 콘텐츠 추가는 JSON 파일 PR로. 시즌 이벤트(명절·계절)는 날짜 범위 필드로 활성화.

### F-4. 콘텐츠 운영

- **콘텐츠 린트 테스트**: ID 중복, 참조 무결성(아이템·체인 존재), 텍스트 변수 유효성, 100유형 모두 도달 가능성(각 유형마다 해당 유형이 뽑히는 최소 픽스처 존재) 검사.

## G. 기술 구현 계획 & 검증 기준

### G-1. 전제
- 스택은 **기존 레포를 확인 후 따른다.** 레포에 없는 경우의 기본값(권장): Next.js(App Router) + TypeScript + Tailwind + Postgres(기존 연결 우선, 없으면 Vercel Marketplace의 Neon/Supabase) + 기존 ORM(없으면 Drizzle) + 기존 인증(없으면 Auth.js 이메일/OAuth 또는 Supabase Auth) + Framer Motion(공 메뉴) + Howler.js(BGM) + Vitest/Playwright.
- 게임 로직은 **프레임워크 독립 순수 TS 모듈** `lib/game/*`로 분리 → 단위 테스트의 핵심.

### G-2. 자정 결산 아키텍처 (서버리스)
- **이중 경로**:
  1. **Vercel Cron**(플랜이 허용하는 최소 주기, Hobby라면 일 1회 제약이 있으니 확인) → `/api/cron/settle`(CRON_SECRET 검증): "현지 날짜가 바뀌었는데 어제 결산이 없는 사용자"를 배치(100명 단위)로 SettlementJob 생성·처리.
  2. **지연(lazy) 결산**: 사용자가 앱을 열거나 API를 호출할 때 `ensureSettled(user)`가 미결산 과거 날짜(최대 최근 60일, 첫 기록일 이후)를 확인해 처리. → Cron 주기 제약·미접속 모두 커버. 오래 미접속 시 공백 날짜는 "쉬어가는 여행자"(096)로 **일괄 결산하지 않고**, 첫 기록일 이후 & 기록 없는 날은 결산 레코드 없이 연대기에 "여관에서 쉰 날"로 표시(선택: 설정에 따라 096 부여). 기본값: 기록 없는 날은 결산 생성 안 함 → 도감 오염 방지. 단 전날까지 연속 기록 중이던 사용자의 단일 공백일은 096 부여.
- **멱등성**: `input_hash` 비교 — 동일하면 재실행 스킵. DB 트랜잭션 + `SELECT … FOR UPDATE` 또는 advisory lock(`pg_advisory_xact_lock(hash(user,date))`)으로 동시 실행 방지. UNIQUE(user,date) final 부분 인덱스로 최종 방어.
- **재결산**: 과거 날짜 로그 생성/수정/삭제 시 해당 `attributed_date`(자정 분할이 걸치면 두 날짜)의 SettlementJob(reason=edit, run_after=now+30s 디바운스) upsert. 처리 시 기존 final → superseded, 새 revision final.
- 오늘 날짜는 결산하지 않음(미리보기 "지금까지의 하루로는 … 에 가까워요"는 선택 기능, 결과 저장 안 함).

### G-3. 동시성·오프라인
- 로그 id는 클라이언트 UUID → 재시도 시 멱등 upsert. `version` 낙관적 잠금(충돌 시 최신 반환 + UI 병합 안내).
- 저장 실패 시 IndexedDB 대기열(outbox)에 보관, 온라인 복귀 시 재전송, 헤더에 "동기화 대기 2" 표시. 진행 중 타이머는 서버에 start만 기록하고 클라이언트 타이머는 표시용.

### G-4. 보안·프라이버시
- 모든 쿼리 `user_id = session.user.id` 강제(서버 레이어 공통 헬퍼), Supabase면 RLS 정책 + 테스트.
- 메모 필드는 외부 전송 금지(AI 옵트인에도 제외). 데이터 내보내기/계정 삭제 제공. 로그에 개인 기록 출력 금지.
- 입력 검증 Zod(details는 metric_schema별 스키마).

### G-5. BGM
- 후보 출처: **OpenGameArt.org의 CC0 트랙**(우선), Kevin MacLeod(incompetech, CC BY 4.0 — 크레딧 필수), Pixabay Music(자체 라이선스 — 조건 확인). 개발 AI는 **라이선스 페이지를 실제 확인**하고 `public/audio/CREDITS.md`와 앱 설정 > 크레딧에 출처·라이선스·저작자를 기록한다. 확인이 불가하면 **코드로 생성한 앰비언트(Web Audio 합성)** 를 임시 폴백으로 쓰고 보고서에 명시.
- 트랙: 로비(주간), 로비(야간) 2곡 + 효과음(공 전개, 저장, 이벤트 희귀도별, 결산 공개). 각 ≤ 2MB(OGG/MP3 96–128kbps), 지연 로딩, 반복 재생 크로스페이드.
- 자동재생: 타이틀의 사용자 제스처로만 시작. 설정은 localStorage + 서버 UserSettings 동기화. 탭 비가시 시 페이드아웃(`visibilitychange`).

## P0-2 기록 UX
- 하단 탭 5개: 홈 / 연대기 / (+) / 도감 / 모험가. 중앙 + 는 솟은 원형 버튼.
- + 탭 시 딤 배경 위로 카테고리 공들이 중심에서 방사형으로 스프링 전개(최대 8개/페이지, 순차 지연). 첫 페이지 = 핀 → 최근 14일 빈도×현재 시간대 적합도 상위. 스와이프/더보기로 다음 페이지, 마지막에 "새 행동 만들기" 공. 진행 중 기록이 있는 공은 빛나고 탭 시 종료 바로가기.
- 공 → 세부 행동 bottom sheet(즐겨찾기 칩 먼저, "+ 새 과목" 등) → 폼. 기본 필드 2~3개 + 기분(선택), 나머지는 "자세히 기록" 접이식. 시간 모드: 지금 시작(타이머) / 방금 끝남(지속시간) / 시간 지정. 최소 2탭 저장.
- 모바일 시·분 휠 피커 컴포넌트(스냅, 5분 단위 기본, 1분 모드, "어제" 토글). 종료<시작이면 자정 넘김으로 해석해 "다음날" 표기.
- 수면: 잠자기/기상 버튼. 10–18시 시작 & 3h 미만이면 낮잠 추천(변경 가능). 밤잠은 기상 현지 날짜에 귀속, 낮잠은 시작일. 16시간 초과 진행 시 기상 시각 입력 유도.
- 운동 종목별 전용 입력(근력 세트 리스트+세트 복사, 유산소 거리/시간/페이스 자동, 유연성, 구기).
- 커스텀 행동 생성 마법사: 이름/아이콘/색 → 특성 최대 2개 또는 성격 태그 → 기록 템플릿. 생성 시 새 공 등장 연출. 커스텀은 태그의 판정 그룹으로 유형 판정에 참여하고 XP 곡선은 시스템과 동일.
- 저장 후 연출: 공 흡수 애니메이션 → XP 토스트 → (발생 시) 이벤트 카드.

## P0-3 결산·100유형·연대기·도감
- lib/game/time.ts: 사용자 timezone 기준 날짜 계산, 자정 분할 집계(23:00–01:30 → 60/90분), DST 안전(Intl/Temporal polyfill 또는 date-fns-tz 등 기존 의존성).
- lib/game/features.ts: 명세 E-1의 DayFeatures 추출(순수 함수).
